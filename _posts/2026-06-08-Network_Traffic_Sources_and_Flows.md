Networks are typically designed with preplanned traffic flows and sources. Intermediary and endpoint sources. Traffic flows can be classified into North-South traffic and East-West traffic.

    - North-South: Moves into and out of the LAN. Traffic that passes through the firewall.
    - East-West: Traffic that starts and stays inside the LAN. This can include the cloud. Traffic that does not pass through the firewall. 

## Sources

### Intermediary Sources
Intermediary sources are the devices that the traffic moves through. Things like switches, routers, firewalls, IDS/IPS, and wireless access points. Traffic coming from these sources would be things like routing protocols (EIGRP, OSPF, BGP), management protocols (SNMP, PING), logging protocols (SYSLOG), and other supporting protocols (ARP, STP, DHCP).

### Endpoint Sources
Endpoint sources are the bulk of network traffic. Things like laptops/desktops, servers, printers, phones/tablets, and cloud resources.

## Flows

### North-South Traffic
North-South traffic should be monitored closely as it is the traffic moving into and out of the network. Protocols like HTTPS, DNS, SSH, IPSec, SMTP, and RDP. Each has an ingress (inbound) and egress (outbound) stream. Configuring firewall rules and properly logging are important for monitoring the traffic.

### East-West Traffic
East-West traffic originates and stays inside the network. Although this traffic came from inside the firewall it should still be monitored. If an attacker gains access to one device it can be used to compromised other devices (lateral movement).

## Observability
Network traffic can be observed and analyzed through multiple sources.

### Logs
Logs are generated by each system, service, and protocol. There are many, many log formats out there and no real standard. Some protocols for standardizing sending of log messages to collectors are Syslog and SNMP. Logs will generally contain the full network packet just the fields deemed useful. (PowerShell can log the full command. and result?)

### Full Packet Capture
If you want to see everything instead of just what the log collects then you can capture the traffic and inspect it directly. Two ways to do this are a physical network tap, or configuring port mirroring. 

**Network Tap**
A network tap is a physical device connected to the network for capturing traffic. The eletrical signal (Ethernet) or light pulse (fiber optic) is copied as it passes, the copy is forwarded to a dedicated monitoring system for analysis while the regular traffic continues on with no delay.

**Port Mirroring**
Port mirroring is the software version of a network tap. A port on the switch can be configured to copy and send all the traffic to another port. Port mirror can have an impact on performance for large amounts of traffic.

**Considerations**
- Placement: Where you place the tap is important for capturing the right traffic without too much extra.
- Duration: Packet captures take up a lot of space. Guess how much space 1GB of traffic takes up on a storage device.
- Performance: Physical taps claim no (or negligable) performance reduction. Port mirroring can cause perfomance issues for large amounts of traffic.

**Tools**
Packet analysis tools:
- Wireshark
- TCPdump
- Snort, Suricata, Zeek

### Network Statistics
Network statistics can be useful for finding anomalies in the network by analyzing metadata about the network traffic. For example, a sudden increase of DNS requests from a specific endpoint may indicate DNS tunneling. 

**NetFlow**
NetFlow is a protocol developed by Cisco that collects metadata about traffic flowing in a network. It is a great way to detect things like C2 traffic, data exfiltration, and lateral movement

**IPFIX (Internet Protocol Flow Information Export)**
IPFIX is essentially a vendor-neutral successor to NetFlow. It includes similar features, but more flexibility about capture fields.
