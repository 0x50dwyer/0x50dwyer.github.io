## Splunk Components
- Forwarder
- Indexer
- Search Head
- Deployment server and License manager

## Forwarder
Forwarders are the parts of Splunk that send data to another instance of Splunk like an indexer or another forwarder. There are 3 types of forwarders in Splunk.

| Forwarder | Description |
| --- | --- |
| Universal forwarder | Only collects and forwards data from an endpoint. No processing is done on the endpoint. |
| Heavy forwarder | A full Splunk Enterprise instance tha can search, index, change, and forward data. Processing can be done on the endpoint. For example, removing sensitive information before sending the data. Some features of Splunk Enterprise are disabled for efficiency |
| Light forwarder | Also a full Splunk Enterprise instance, but with more features diabled. Deprecated and replaced with the universal forwarder. But, it's probably still out there somewhere. |

### Univeral Forwarder

"The universal forwarder is a dedicated, streamlined version of Splunk Enterprise that contains only the essential components needed to forward data. The universal forwarder does not support python and does not expose a UI." - [Splunk](https://docs.splunk.com/Splexicon:Universalforwarder)

It can be installed on many different platforms and can forward any log data including Windows event logs, server logs, network logs, message queues, archive files. However, it only forwards unparsed data. If you want to forward and route data based on event-based data (source or type of event) then you will need to use a heavy forwarder.

## Installation

Splunk can be installed on a single system or distributed across many different systems. 
This install will consist of a central linux (Ubuntu) install and forwarders on 2 Windows systems and another linux VM.
<ol>
    <li>Check the system requirements to make sure that everything can run Splunk before going through the install process.</li>
    <li>Download the correct installation files for the intended system. Check the hash to make sure that it hasn't been corrupted or tampered with.</li>
    {% include image.html image_src="/assets/images/splunk/splunk_hash_check.jpg" alt_text="Splunk hash checked out" %}   
    <li>For the <a href="https://help.splunk.com/en/splunk-enterprise/get-started/install-and-upgrade/10.4/install-splunk-enterprise-on-linux-or-macos/install-on-linux#id_2a04bd1c_e357_44a5_82bd_e6f403065e8d--en__Install_on_Linuxhttps://help.splunk.com/en/splunk-enterprise/get-started/install-and-upgrade/10.4/install-splunk-enterprise-on-linux-or-macos/install-on-linux#id_2a04bd1c_e357_44a5_82bd_e6f403065e8d--en__Install_on_Linux">Linux installation</a> follow the instructions for the correct package. This one is using the .deb for installation and defaults to the /opt/splunk directory.</li>
    {% include image.html image_src="/assets/images/splunk/splunk_install_complete.jpg" alt_text="Don't forget sudo! When you run dpkg -i" %}
    <li>After install completes you can start Splunk for the first time. Scroll through the legal stuff. If you agree then enter 'y' and you will be prompted to create an administrator account. Create the username and password. Make sure to remember it.</li>
    {% include image.html image_src="/assets/images/splunk/splunk_admin_user.jpg" alt_text="Create the admin account. Don't forget the password" %}
    <li>If everything goes smoothly you should get a message saying the Splunk web interface is at http://127.0.0.1:8000 or http://(hostname):8000. </li>
    {% include image.html image_src="/assets/images/splunk/splunk_interface_up.jpg" alt_text="The Splunk interface is up. Yay!" %}
    <li>Open the browser and head to that URL. The Splunk login page should load where you can enter the admin credentials you just created.</li>
    {% include image.html image_src="/assets/images/splunk/splunk_web_login.jpg" alt_text="Splunk web login. Remember that password?" %}
    <li>We're in !!! Now what? Let's get some data into this so we have something to search.</li>
